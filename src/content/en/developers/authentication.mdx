SokoPlus uses **JWT bearer tokens** for all authenticated requests. Tokens are issued after login, OTP verification, or Google sign-in.

## Getting a token

### Email + password login

```bash
curl -X POST https://api.sokopluss.co.tz/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "you@example.com", "password": "secret"}'
```

<CodeBlock title="Response">
```json
{
  "status": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": { "id": "...", "email": "you@example.com", "role": "client" }
  }
}
```
</CodeBlock>

### OTP (registration & recovery)

1. `POST /auth/signup` with your details → sends a 6-digit code.
2. `POST /auth/otp/verify` with the code → returns a JWT for new users.
3. Password reset uses the same flow: `/auth/forgot-password/send` → `/verify` → `/reset`.

### Google sign-in

`POST /auth/google` with the Google OAuth token from your web client ID.

## Using the token

Send it on every authenticated request:

```bash
curl https://api.sokopluss.co.tz/api/user/profile \
  -H "Authorization: Bearer <token>"
```

## Auth endpoints

| Method | Path | Description |
|--------|------|-------------|
| POST | `/auth/signup` | Start registration (sends OTP) |
| POST | `/auth/login` | Email + password login |
| POST | `/auth/otp/send` | Send verification OTP |
| POST | `/auth/otp/verify` | Verify OTP (returns JWT if new user) |
| POST | `/auth/otp/link` | Link a phone number to an account |
| POST | `/auth/google` | Google OAuth sign-in |
| POST | `/auth/logout` | Invalidate the session |
| POST | `/auth/refresh` | Refresh a token |
| POST | `/auth/forgot-password/send` | Send reset OTP |
| POST | `/auth/forgot-password/verify` | Verify reset code |
| POST | `/auth/forgot-password/reset` | Set a new password |
| GET | `/auth/me` | Current user profile (with business) |
| POST | `/auth/check-exists` | Check whether a user exists |

## Token validation

The `protect` middleware:

- Decodes the JWT from the `Authorization` header.
- Loads the user from the database.
- Rejects users who are soft-deleted, suspended or disqualified.
- Attaches the user to `req.user`.

<Callout type="warning">
401 responses mean your token is missing, expired or the user is blocked. Re-authenticate to continue.
</Callout>

Role-based access control is applied on top of JWT auth across the API.
