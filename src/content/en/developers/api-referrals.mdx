The referral program and the credits system are one feature, controlled by a single flag `ecommerce:referral_credits`. When the flag is disabled, the user-facing endpoints below return `503` with the configured message; the admin endpoints are unaffected.

<CodeBlock title="Feature disabled (503)">
```json
{
  "message": "Referral system is currently unavailable",
  "feature": "referral_credits",
  "enabled": false
}
```
</CodeBlock>

All endpoints require a JWT. Admin endpoints additionally require the `superAdmin` role.

## Referral rewards

Credits are awarded when a referral is marked completed:

| Who | Credits | Description |
|-----|---------|-------------|
| Referrer | 5,000 | Referral reward for referring a user |
| Referred user | 2,000 | Welcome bonus for being referred |

A completed referral records `rewardAmount: 7000` (5,000 + 2,000). Earned credits expire after **6 months**.

## Referrals (`/api/referrals`)

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/referrals/my` | JWT | The current user's referred users |
| GET | `/referrals/stats` | JWT | Referral statistics |
| GET | `/referrals/code` | JWT | Your referral code (generates and persists one if missing) |
| POST | `/referrals/apply` | JWT | Apply someone's referral code |
| GET | `/referrals/admin/all` | superAdmin | All referrals (paginated) |

### GET /referrals/my

<CodeBlock title="Response">
```json
{
  "referrals": [
    {
      "id": "...",
      "status": "pending",
      "expiresAt": "2026-11-07T00:00:00.000Z",
      "rewardAmount": null,
      "createdAt": "2026-08-07T00:00:00.000Z",
      "referred": { "id": "...", "fullName": "Jane Doe", "email": "jane@example.com", "createdAt": "2026-08-07T00:00:00.000Z" }
    }
  ]
}
```
</CodeBlock>

### GET /referrals/stats

<CodeBlock title="Response">
```json
{
  "stats": {
    "totalReferrals": 3,
    "completedReferrals": 1,
    "pendingReferrals": 2,
    "totalCreditsEarned": 7000
  }
}
```
</CodeBlock>

### GET /referrals/code

Returns the current user's referral code, generating and persisting one when it is missing. Codes follow the `SP-` prefix followed by 8 characters (`A`–`Z`, `0`–`9`).

<CodeBlock title="Response">
```json
{ "referralCode": "SP-AB12CD34" }
```
</CodeBlock>

### POST /referrals/apply

<CodeBlock title="Request">
```json
{ "referralCode": "SP-AB12CD34" }
```
</CodeBlock>

| Status | Case |
|--------|------|
| `200` | Code applied — `{ "message": "Referral code applied successfully" }` |
| `400` | Missing code, code already applied, or using your own code |
| `404` | Invalid / unrecognised code |

A referral code can only be applied once, and never to your own code. The referral record starts as `pending`.

### GET /referrals/admin/all

Query params `page`, `limit` (default `1`, `20`) and an optional `status` filter.

<CodeBlock title="Response">
```json
{
  "referrals": [ ... ],
  "pagination": { "page": 1, "limit": 20, "total": 42, "pages": 3 }
}
```
</CodeBlock>

## Credits (`/api/credits`)

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/credits/my` | JWT | Current credit balance |
| GET | `/credits/history` | JWT | Credit transaction history |
| POST | `/credits/redeem` | JWT | Redeem credits for a feature |
| GET | `/credits/admin/user/:userId` | superAdmin | A user's credits + transactions |
| POST | `/credits/admin/adjust` | superAdmin | Manually adjust a user's credits |

### GET /credits/my

<CodeBlock title="Response">
```json
{
  "credits": {
    "id": "...",
    "userId": "...",
    "balance": 5000,
    "totalEarned": 5000,
    "totalRedeemed": 0,
    "totalExpired": 0
  }
}
```
</CodeBlock>

### GET /credits/history

<CodeBlock title="Response">
```json
{
  "history": [
    {
      "id": "...",
      "type": "earned",
      "amount": 5000,
      "description": "Referral reward for referring user",
      "referenceType": "referral",
      "referenceId": "...",
      "expiresAt": "2027-02-07T00:00:00.000Z",
      "createdAt": "2026-08-07T00:00:00.000Z"
    }
  ]
}
```
</CodeBlock>

Transaction `type` values: `earned`, `redeemed`, `adjusted` (admin), `expired`.

### POST /credits/redeem

Body `{ "feature": "...", "amount": ... }` — `amount` is optional and defaults to the feature's cost.

| Feature | Cost (credits) |
|---------|----------------|
| `product_boost` | 500 |
| `service_pin` | 500 |
| `featured_listing` | 1,500 |
| `pro_trial` | 2,000 |
| `pro_month` | 5,000 |
| `business_month` | 10,000 |

<CodeBlock title="Request">
```json
{ "feature": "product_boost" }
```
</CodeBlock>

<CodeBlock title="Response">
```json
{
  "message": "Credits redeemed successfully",
  "credit": { "id": "...", "userId": "...", "balance": 4500, "totalEarned": 5000, "totalRedeemed": 500, "totalExpired": 0 }
}
```
</CodeBlock>

An invalid feature returns `400` with a `validFeatures` list; an insufficient balance returns `400` with `Insufficient credits`.

<Callout type="note">
Credits are spent by redeeming them for a platform feature via `POST /credits/redeem` — they are not deducted automatically at order checkout.
</Callout>

### GET /credits/admin/user/:userId

<CodeBlock title="Response">
```json
{
  "user": { "id": "...", "fullName": "Jane Doe", "email": "jane@example.com" },
  "credits": { "id": "...", "userId": "...", "balance": 5000, "totalEarned": 5000, "totalRedeemed": 0, "totalExpired": 0 },
  "transactions": [ ... ]
}
```
</CodeBlock>

### POST /credits/admin/adjust

<CodeBlock title="Request">
```json
{
  "userId": "...",
  "amount": 1000,
  "description": "Promotional bonus"
}
```
</CodeBlock>

`amount` must be a non-zero number. Positive values increment `totalEarned`; negative values increment `totalRedeemed` and are rejected with `400` when they exceed the current balance.

<CodeBlock title="Response">
```json
{ "message": "Credits adjusted successfully", "credit": { ... } }
```
</CodeBlock>
